# Security Policy

## Supported versions

Security fixes are provided for the latest release line. Older releases are
not actively maintained unless a maintainer states otherwise.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Older releases | No |

## Reporting a vulnerability

Please use GitHub's
[Private Vulnerability Reporting](https://github.com/1273984347/mediascribe/security/advisories/new)
to report a security issue. Do not open a public issue or pull request that
contains vulnerability details, exploit code, credentials, or private data.

If private reporting is not available, open a public issue that only asks the
maintainers to enable a private reporting channel. Do not include the
vulnerability details in that issue.

A useful report includes:

- The affected MediaScribe version and operating system.
- A clear description of the vulnerability and its impact.
- Minimal reproduction steps or a proof of concept.
- Sanitized logs, with tokens, cookies, API keys, and personal data removed.

Please give maintainers time to investigate and coordinate a fix before
publishing details publicly.

## Response targets

- Acknowledge a report within 7 days.
- Provide an initial assessment within 14 days.
- Coordinate disclosure and release timing with the reporter.

These are best-effort targets, not guarantees.

## Scope

Report vulnerabilities in MediaScribe's code, packaging, documentation
examples, or default configuration. Do not report issues that only affect a
third-party platform, model, or dependency unless MediaScribe's use of that
component creates the vulnerability.
