# 🎬 MediaScribe 使用说明

> 本文档对应 v3.4.0+。更完整的文档（含 Web UI / MCP / 插件）见 [README](https://github.com/1273984347/mediascribe/blob/main/README.md) 与 `docs/`。

## 🚀 三步上手

```bash
# 1. 安装（PyPI 最小安装，含默认 ASR 引擎）
pip install "mediascribe[faster-whisper]"
# 源码安装可改为：pip install -e ".[faster-whisper]"
playwright install chromium   # 抖音/小红书需要

# 2. 环境自检（推荐首次先跑）
python -m mediascribe doctor

# 3. 在线首次转录：显式授权下载缺失模型权重
python -m mediascribe transcribe "https://www.bilibili.com/video/BV1Nd596vEyU" \
  --allow-model-download
```

普通 `transcribe` / `verify` 默认**不会下载模型权重**。离线使用请先按
[Configuration](configuration.md#model-weight-caches) 预置所选引擎的权重，再运行：

```bash
python -m mediascribe doctor --offline
python -m mediascribe transcribe "video.mp4" --language zh
```

`transcribe` 没有 `--offline` 参数；离线路径是“预置权重 + 不传
`--allow-model-download`”。Web / MCP 最小安装分别使用
`mediascribe[web,faster-whisper]` 与 `mediascribe[mcp,faster-whisper]`。
`requirements.txt` 是源码/开发安装 shim（展开为
`-e .[web,faster-whisper,whisper,mcp]`），不是纯基础依赖；`[all]` 不含 `[vad]`。

## 📌 命令总览

| 命令 | 用途 |
|------|------|
| `python -m mediascribe transcribe <输入>` | 转录单个视频/音频/公众号文章 |
| `python -m mediascribe batch <输入...> \| --file list.txt` | 批量转录 |
| `python -m mediascribe archive --user <主页URL> -n 20` | 批量转录某创作者的主页视频 |
| `python -m mediascribe verify <转录稿.md>` | 对已有转录稿做交叉复核 |
| `python -m mediascribe learn ...` | ASR 术语自动学习（越用越准） |
| `python -m mediascribe profile <run.jsonl>` | 渲染性能报告 |
| `python -m mediascribe doctor [--offline]` | 环境自检（ffmpeg/GPU/引擎/模型缓存/cookies） |
| `python -m mediascribe events list\|export\|clear\|metrics` | 查看、导出、清空本地事件或计算指标 |

无参数直接运行 `python -m mediascribe` 会打印快速开始引导。

## ⚙️ 常用参数

标准默认组合是 **`faster-whisper` + `small`**。未安装 faster-whisper 时回退到
`whisper` 并给出提示；WhisperX 只有显式指定 `--engine whisperx` 才会使用。

```bash
# 更大模型：large-v3 是模型名，不是引擎；更准但更慢、更吃显存
python -m mediascribe transcribe video.mp4 -e faster-whisper -m large-v3 -l zh

# 模型按音频时长自动推荐（短→medium，中→small，长→tiny；粤语 -l yue 恒选 large-v3）
python -m mediascribe transcribe video.mp4 --model auto

# 默认按 ASR 分段；--timestamps 才给每段加 [mm:ss]
python -m mediascribe transcribe <URL> --timestamps

# 双模型交叉校对: 主稿后用 small 重转同一条音频, 生成分歧复核清单
# (<转录稿>.crosscheck.md), 人工只需复核清单上的位置
python -m mediascribe transcribe <URL> --cross-check small

# 在线复核缺少权重时显式授权下载
python -m mediascribe verify output/transcripts/<转录稿>.md --allow-model-download

# 转录成功后自动清理中间媒体(downloads/ + audio/, 腾磁盘;
# transcripts/metadata/wiki 永不触碰; 也可写配置键 cleanup_media
# 或环境变量 MEDIASCRIBE_CLEANUP_MEDIA=1)
python -m mediascribe transcribe <URL> --cleanup-media

# 常用参数写进配置文件，以后不用重复敲
python -m mediascribe --config mediascribe.json transcribe <URL>
```

`-e/--engine` 的可选值是 `whisper`、`faster-whisper`、`whisperx`、`whisper-cpp`；
`large-v3` 只能传给 `-m/--model`，不能作为引擎。

`mediascribe.json` 示例（CLI 显式参数优先于配置文件）：

```json
{
  "engine": "faster-whisper",
  "model": "large-v3",
  "language": "zh",
  "device": "auto",
  "timestamps": true
}
```

模型速度/质量参考：`tiny` < `base` < `small`（默认）< `medium` < `large-v3`（中文最佳）。
模型权重按引擎分别缓存，具体位置见
[Configuration](configuration.md#model-weight-caches)。

## 📂 输出在哪

按类型平铺在 `output/` 下：

```text
output/
├── downloads/        # 源视频/音频（持久下载缓存默认关闭）
├── audio/            # 提取的音频
├── transcripts/      # 转录稿 <来源名>-<时间戳>.md（如 douyin_<视频ID>-20261001-003629.md）
├── metadata/         # 运行元数据 (json, 与转录稿同名)
└── LATEST.txt        # 最新默认产物指针
```

- 转录完成后终端会打印转录稿路径，同时写入 `output/LATEST.txt`；`--output`
  自定义输出时不覆盖该指针。
- `LATEST.txt` 可能指向单份转录稿，也可能指向 archive 的汇总报告，取决于最近
  一次运行。
- `--output 路径.md` 可自定义输出位置。
- 人工审校后的交付稿放 `output/wiki/`（见仓库既有样例）。

### 转录稿长什么样（v3.4.0 起）

```markdown
# <平台真实标题>            ← 不再是 douyin_xxx.mp4 文件名

## 基本信息
- **平台**: 抖音
- **作者**: ...
- **时长**: 4分14秒
- **来源**: <原文链接>
- **转录引擎**: faster-whisper
- **转录模型**: large-v3

## 转录内容
**[00:00]** 第一段...        ← 仅在 --timestamps 下显示
**[01:32]** 第二段...
```

### 输出质量三档

| 档位 | 开关 | 效果 |
|------|------|------|
| ① 分段稿（默认） | 无需配置 | 按 segments 分段 + 真实标题 + 元数据头；默认无时间戳 |
| ② 术语自动校正 | 默认开启，`learn` 积累越多越准 | 专有名词自动纠正（如 霍去病/福尔摩斯类同音错） |
| ③ LLM 润色 | 显式 opt-in | 补标点、按语义分段、修同音字 |

开启 LLM 润色（任何 OpenAI 兼容 API，失败自动回退原文）：

```bash
export MEDIASCRIBE_LLM_ENABLED=1
export MEDIASCRIBE_LLM_API_BASE="https://api.deepseek.com"
export MEDIASCRIBE_LLM_API_KEY="sk-..."
```

LLM 后处理默认关闭；缺失 API key 时自动禁用，不会发起请求。启用后会把最多
`MEDIASCRIBE_LLM_MAX_CHARS` 字符的截断转录文本，以及标题、来源类型和来源 URL
发往配置的 API。

校对稿件后喂回术语库，下次转录自动应用：

```bash
python -m mediascribe learn edit --original <ASR原稿> --corrected <你的校对稿>
```

## 📊 进度语义

Web / WebSocket 使用六个阶段：
`preflight → model_prepare → download → extract_audio → transcribe → assemble`。
进度是阶段级切换/完成信号，**不是当前阶段内部的实际百分比**，也不能据此推断
精确 ETA。

## 👤 批量转录创作者主页

```bash
# 从创作者主页 URL
python -m mediascribe archive --user "https://www.douyin.com/user/xxx" -n 20

# 从单条视频反推创作者
python -m mediascribe archive --from-video "https://v.douyin.com/xxxxx/" -n 10
```

断点续传：重跑同一条命令会自动跳过已成功的视频、只重试失败项。默认汇总报告写在：

```text
output/summary_<时间戳>.md
output/results_<时间戳>.json
output/summary.md       # 最新汇总的固定名副本
output/results.json     # 最新结果的固定名副本
```

archive 输出目录中的 `LATEST.txt` 指向最新汇总 Markdown。

## 🤖 Agent / MCP 契约

`--json` 与 `--bilingual-json` 只覆盖 `archive` / `mediascribe-batch`，不是所有
CLI 命令的通用参数；输出 schema 为 `mediascribe.agent-output/v1`。

MCP 的 `transcribe_video` 使用以下参数名：

* 必填：`source`
* 常用可选：`whisper_model`、`output_dir`、`engine`、`language`、
  `allow_model_download`

不要使用旧的 `url_or_path`、`model`、`output` 名称。

## 本地事件与指标

```bash
python -m mediascribe events list
python -m mediascribe events export --output output/events.json
python -m mediascribe events metrics
python -m mediascribe events clear
```

事件只保留在本机 SQLite，默认保留 **90 天**。`clear` 清空历史但保留安装身份和
首次运行标记。指标按安装 ID 去重：提交率/成功率的分母是新安装数，打开率的
分母是成功安装数，恢复成功率的分母是选择过恢复动作的安装数；内部测试事件
不计入，分母为零时返回 `null`。

## 可选能力边界

* `pip install "mediascribe[vad]"` 只为 Python API 的 `ChunkedTranscriber`
  提供 VAD 分块能力，不会自动改变普通 `transcribe`。
* 持久下载缓存默认关闭，需显式设置 `MEDIASCRIBE_DOWNLOAD_CACHE=1`。
* `PersistentChunkCache` 目前只是库类，没有接入 CLI / Web / MCP 用户路径。

## ⚠️ 注意事项

1. **ffmpeg 必须在 PATH 中**（`doctor` 会检查）。
2. **模型权重默认不下载**；在线首用显式传 `--allow-model-download`，离线先预置权重。
3. **耗时参考**（40 分钟视频）：faster-whisper + GPU 数分钟；CPU + large 级别可能 1 小时+。
4. 微信公众号登录墙文章需要 cookies：`--wechat-cookie-file cookies.txt`。
