### 1.4 两个必须解决的机制问题

**① patch 语义** —— `mock.patch("app._build_pipeline")` 要求被 patch 的名字在
**调用时**从 app 模块的全局查找。而测试顺序是「**先 `create_app()`，再 patch**」：

- 路由函数留在 app.py → 闭包在调用时查 app 全局 ⇒ patch 生效；
- 路由函数搬到子模块 → 闭包在子模块全局找 ⇒ patch 失效；
- 「在 `create_app` 时把 `_build_pipeline` 当参数传进路由模块」⇒ **也失效**，
  装配期就把原函数捕获了。

⇒ 解法：**间接一层工厂**，查找发生在调用时：

```python
def _pipeline_factory(req, workspace):
    """构造 Pipeline —— 委托 app 模块的 ``_build_pipeline``。"""
    return _build_pipeline(req, workspace)
```

`create_app` 传 `_pipeline_factory`（不是 `_build_pipeline`）。

**② 双路径加载** —— 测试既用 `import app`（裸模块，测试把 `mediascribe/web`
插进 `sys.path`）又用 `import mediascribe.web.app`（包路径）。若子模块用
**相对导入**，两条路径会各拿**一份**子模块实例 ⇒ `_RateLimiter` 这类
**类对象 identity 分叉**，`isinstance` 判断失效。

⇒ 解法：子模块 import 一律用**绝对路径** `from mediascribe.web.x import Y`。

### 1.5 风险与回滚

- 风险①：搬移时漏改依赖 ⇒ 用 `ruff --select F821` 一次性查全（比逐个跑测试快得多）。
- 风险②：装饰器被落单 ⇒ `ast.ClassDef.lineno` 不含装饰器行，`@dataclass` 会留在原文件。
- 风险③：ruff F401 把「有意的 re-export」判成未使用 ⇒ 用 `__all__` 显式列出。
- 回滚：纯移动 + 少量测试改造，`git checkout` 即回。

## 四、复盘

### 做对的

- **先盘点约束再动手**：把测试里所有 `from app import` / `mock.patch` / `assertLogs`
  提成一张表，后面所有设计都从这张表推导，而不是拆完再修。
- **脚本搬移而非手抄**：AST 定位区间 + 逐字切片，函数体零手写 ⇒ 没有笔误风险。
- **`ruff --select F821` 当"缺失依赖清单"**：一次列出 10 余处缺失，比逐个跑测试
  定位快一个数量级。
- **改动分两批**：每批搬完就跑测试，失败面始终局限在一批内。

### 做得不好的

- **第一轮 grep 漏了"裸模块名"形态**：只搜 `mediascribe.web.app.` 没搜 `"app.`，
  导致 `mock.patch("app._build_pipeline")` 这条约束**在设计阶段没被发现**，
  一直埋到批 2 才炸。⇒ 盘点依赖时，同一个符号的**所有**引用形态都要列出来。
- **依赖注入方案第一版是错的**：我最初设计成「`create_app` 直接把 `_build_pipeline`
  传给路由」，它满足了"patch 点在 app 模块"，却**没考虑 patch 发生在 create_app
  之后** ⇒ 装配期捕获 ⇒ patch 失效。⇒ 设计 patch 语义时必须想清楚「查找发生在
  装配期还是调用期」。
- **搬移脚本的装饰器坑**：`ast` 的 `lineno` 不含装饰器，第一版脚本把
  `@dataclass` 落单在原文件，症状是 `AttributeError: 'function' object has no
  attribute '__mro__'` —— 报错信息与「装饰器丢了」八竿子打不着，定位花了一轮。

### 意外的收获

- **旧测试固化的断言会集体失效**：这次 4 处失败**全部**是「测试指向了旧位置」，
  而不是代码坏了。这类失败其实是好事 —— 它逼着人确认「这个测试的意图是什么」，
  而不是简单改个路径糊过去。改的时候都在注释里写清了「意图不变，只是位置变了」。
- **`__all__` 兼作公共 API 清单**：为了压住 ruff 的 F401 顺手加的 `__all__`，
  意外成了「app 模块对外暴露什么」的可读清单（55 个名字）。
