## 一、执行前计划

### 1.1 目标

用户在「现在的 web 网页怎么样」这一问后，要求把实测发现的三处问题一次修净，并追加修掉「前端改动看不到效果」的缓存隐患：

1. **版本号漂移** —— 同一产品在三处各说各话：`/api/health` 说 `3.2.0c`、页脚说 `v3.3.0`、包真源是 `3.3.0`。
2. **次级文字对比度不足** —— 浅色主题下 `.hint` 与 `::placeholder` 低于 WCAG AA。
3. **首屏整块白闪** —— 入场动画把主体钉在首帧 `opacity:0`。
4. **静态资源被浏览器缓存** —— 改完前端样式，页面仍是旧的。

**对比度实测**（WCAG 2.1 相对亮度公式，背景取该主题最亮底色）：

| 变量 | 原值 | 落点背景 | 原对比度 | 判定 |
|---|---|---|---:|---|
| 浅色 `--fg-3` | `rgba(0,0,0,0.38)` | `#ffffff` | **2.76:1** | ✗ 远低于 AA |
| 浅色 `--fg-2` | `rgba(0,0,0,0.56)` | `#ffffff` | 5.10:1 | ✓ |
| 暗色 `--fg-3` | `rgba(255,255,255,0.26)` | `#181817` | **2.35:1** | ✗ 远低于 AA |
| 暗色 `--fg-2` | `rgba(255,255,255,0.56)` | `#181817` | 6.29:1 | ✓ |

`.hint`（`styles.css:147`）与 `::placeholder`（`styles.css:161`）**都**用 `--fg-3` ⇒ 两主题的这两类文字都不达标；暗色还是**默认主题**，比浅色更该修。

**首屏白闪的机制**（`styles.css:111-116` 改前）：

```css
main > * { animation: rise 0.4s … both; }
main > *:nth-child(2) { animation-delay: 0.05s; }   /* …到 0.2s */
@keyframes rise { from { opacity: 0; transform: translateY(10px); } }
```

`animation-fill-mode: both` 让元素在**动画开始前**就套用 `from` 帧（`opacity:0`），叠加 `nth-child` 延迟链 ⇒ 首屏最长 0.6s 内主体整块全透明，表现为「白闪一下」。

**缓存根因**（第 4 项，计划阶段追加）：Starlette 0.52.1 的 `StaticFiles.__init__` 签名**没有 `headers` 参数**（只有 `directory/packages/html/check_dir/follow_symlink`）⇒ 不发 `Cache-Control` ⇒ 浏览器按启发式规则长期持有旧资源。计划阶段实测：改完 CSS 后浏览器截图字节数与改前**完全相同**（35562 bytes），而服务端 HTTP 拉取已是新版 ⇒ 确证是缓存。

### 1.4 风险与回滚

- 风险①：把 `__version__` 导入放到 `mediascribe/web/app.py` **顶层**会拖整个 ASR 栈（torch）进 Web 启动路径 → 改为在 `create_app()` **函数体内**导入（该函数本就已在函数内 `from mediascribe.progress import ProgressRegistry`）。
- 风险②：改版本号可能击穿依赖版本字面量的旧测试 → 已预期（见 §2.2），逐条改为引用真源。
- 风险③：纯 ASGI 中间件覆写 `file_response` **覆盖不到 304 路径**（协商缓存命中走另一条返回分支）→ 改为包裹整个 mount 的纯 ASGI 中间件，200 与 304 都经手。
- 回滚：本批仅动 Web 层与测试，`git revert` 即可，无数据迁移。

### 步骤 1：版本号收敛为单一真源

> 为什么不让前端自己填版本：会闪一下（先空后有）；服务端注入是首帧即正确。

### 步骤 2：对比度修到 WCAG AA

| 变量 | 原值 | 新值 | 新对比度 |
|---|---|---|---:|
| 浅色 `--fg-2` | `rgba(0,0,0,0.56)` | `rgba(0,0,0,0.66)` | 7.3:1 |
| 浅色 `--fg-3` | `rgba(0,0,0,0.38)` | `rgba(0,0,0,0.55)` | 4.8:1 |
| 暗色 `--fg-3` | `rgba(255,255,255,0.26)` | `rgba(255,255,255,0.48)` | 4.9:1 |

浅色 `--fg-2` 一并从 0.56 提到 0.66，是因为 `--fg-3` 提到 0.55 后两者几乎无差 ⇒ **三级文字层级会塌陷**；提到 0.66 后梯度为 17.5 : 7.3 : 4.8，清晰且全部达标。

### 步骤 3：首屏白闪修复

```css
main > * { animation: rise 0.25s cubic-bezier(0.2, 0.7, 0.2, 1) both; }
@keyframes rise { from { opacity: 0.35; transform: translateY(8px); } }
```

删掉 4 条 `nth-child` 延迟链（错峰感让位于「首帧即有内容」），时长 0.4s → 0.25s，`from` 帧保留 0.35 透明度 ⇒ 首帧不再是全透明。

### 步骤 4：静态资源缓存修复（两层，缺一不可）

1. **页面引用带版本**：`index.html` / `wiki.html` 的 CSS 与入口 JS 引用加 `?v={{STATIC_VERSION}}`；`{{STATIC_VERSION}}` 由后端按 `static/` 下最新文件 mtime（毫秒）注入 ⇒ 改任何前端文件，URL 即变。
2. **响应头兜底**：`/static/*` 加 `Cache-Control: no-cache, must-revalidate`。
   ⇒ **第 2 层不可省**：ES module 内部 `import "./modules/theme.js"` 路径是**静态写死**的，query 参数根本管不到它们；改 `modules/*.js` 仍会被浏览器缓存住。
   ⇒ 实现上用**纯 ASGI 中间件包裹整个 mount**（而非覆写 `StaticFiles.file_response`），因为协商缓存命中的 304 走的是另一条返回分支、不经过 `file_response`，覆写会漏头。

### 步骤 5：测试与文档

- 新增 `tests/test_version_consistency.py`（6 条）：真源一致性、pyproject 对齐、`app.version` 对齐、`/api/health` 对齐、页脚注入、**防回退**（Web 层不得再出现硬编码版本字面量）。
- `tests/test_web_app_static.py` 新增 `TestStaticCacheControl`（4 条）：CSS/模块响应头带 `no-cache`、模板引用带版本占位符、渲染后占位符已解析。
- `tests/test_web_app_static.py` 的资源引用正则 `(/[^"#?]+)"` **原本会跳过带 query 的路径** ⇒ 新引用匹配不到，测试会静默失去覆盖对象 ⇒ 改为允许 query 并在取用时去 query。
- `docs/web-ui.md` 同步。

### 步骤 6：单文件离线预览版（追加项）

用户在得知「Web UI 的 HTML 是服务端模板、不能双击打开」后，要求补一个**能双击打开
就完事的独立 HTML 文件**。新增 `scripts/tools/build_standalone_web.py`：

- **ES module 图 → IIFE 闭包序列**：`import { a } from './x.js'` → `const { a } = __mod_x;`；
  `export { a, b }` → `return { a, b };`；按依赖拓扑序 `dom → theme/status/gpu/auth → jobs`
  展开。**保留模块闭包语义**是为了避免跨模块同名符号冲突（`dom.js` 与 `status.js` 都有
  `statusEl`，直接平铺会重复声明）。
- **内联 CSS** 进 `<style>`，**替换占位符**（`{{APP_VERSION}}` 取自 `mediascribe/_version.py`，
  `{{STATIC_VERSION}}` 用 mtime 毫秒），**注入离线适配层**（`file://` 下拦截 `fetch` /
  `WebSocket`，给出可读提示而不是 `Failed to fetch`）+ 页面顶部横幅。
- 转换规则未覆盖住时**直接报错退出**，不产出半坏的文件（断言期望命中数：`<link>` 与
  `<script>` 各须匹配 1 处、占位符须零残留、转换后不得残留 import/export 语句）。
- 产物：`output/web-standalone/mediascribe-web-standalone.html`（43.8 KB，自包含）。

## 四、复盘

### 做对的

- **取证用双证据**：视觉问题同时取「API 响应」与「浏览器截图」，避免把「代码改了」当成「效果生效了」。首屏白闪就是靠**首帧截图**才暴露的 —— 读代码只会看到「有个入场动画」。
- **一致性测试 + 反向验证**：§3.3 的三次破坏实验，把「我写了个测试」升级为「这个测试确实有效」。
- **尊重门禁的失败**：门禁三次变红，每次都是真问题（见 §五），没有一次是「环境问题」。

### 做得不好的

- **在含 `input[type=password]` 的页面做完整 DOM 快照查询，触发 Browser 的「认证接管」安全分类，把 bash / 文件编辑 / mavis 全部锁死**，前后三次（`inspect` ×2、`query(kind="semantic")` ×1）白等 runtime 重启。根因是取证方式选错：判据其实是**「返回结果里有没有 password 元素」**，而不是「用的哪个 action」—— 实测 `semantic` 查「暗面」（只返回按钮）不触发，查「视频链接」（返回整个表单含 `api-token`）就触发。**这是本次最大的时间浪费。**
- **把「浏览器交互」当成唯一取证路径**。其实后端 API + WebSocket 客户端能给出**更强**的证据（完整事件流），且不受浏览器门禁影响 —— 应该在第一次受阻时就切过去，而不是再问一轮授权。
- **把版本号改成后端注入，代价是源文件不再自包含** —— 改之前双击 `index.html` 至少能看到正确的 `v3.3.0`；改之后页脚直接露出 `{{APP_VERSION}}`，「打开源码像坏了」的观感更强。缓解：两个 HTML 头部加注释写明「这是模板 + 为什么双击会坏 + 正确用法」，并另做了单文件离线预览版。

### 意外的收获

- **门禁三次变红，暴露的是「旧值被测试固化」**：尤其 `test_health_reports_v320c_version` 把漂移的 `"3.2.0c"` 断言成期望值 —— 说明这个漂移**被测试保护了很久**，改对反而会让测试变红。修正确实比看起来难。
- **Starlette 的 `StaticFiles` 没有 `headers` 参数**（0.52.1 签名实测），且 **304 路径不经过 `file_response`** ⇒ 「加个响应头」这件小事有两层实现陷阱。
- 追加的缓存修复，价值超出预期：它不只解决这一次「改样式看不到」，而是**根治了此后每次改前端都要跟浏览器缓存搏斗**的问题。

## 五、经验沉淀

三条跨项目通用教训已写入 Agent Memory（`MEMORY.md`）：

1. **Browser 的 `inspect` 遇到含密码输入框的页面会锁死全部工具，且 `ask_user` 解不开** —— 触发条件与是否真需鉴权无关 ⇒ 必然复发；对策是改用 `query`/`screenshot`，一次受阻即切后端 API。
2. **Starlette `StaticFiles` 不发 `Cache-Control` ⇒ 浏览器缓存旧前端资源** —— 修法必须两层（`?v=<mtime>` + `no-cache` 响应头），因 ES module 内部 import 无法加 query。
3. **改「引用的形态」比改「值」更容易击穿测试里的字面量断言** —— 断言要写成形态不敏感（正则/前缀/引用真源）；门禁变红的第一条失败就是「被固化的旧值」清单。
