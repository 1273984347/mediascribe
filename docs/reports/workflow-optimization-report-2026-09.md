## 6. 工作流优化方案

**核心端到端流程**(本期实测,「用户指令 → 交付」):

```
需求澄清(5-10min) → 实现(10-60min) → 本地测试(0.1-3min)
→ 浏览器验收(1-2min) → commit+push(1min) → CI Tests+bandit(5-8min) → 汇报
```

**瓶颈实测**:CI 环节是唯一串行等待(5–8 分钟);本期 14 次 Tests 推送中 **4 次红灯**,每次红灯 = 1 轮修复 + 1 轮重推(额外 10–15 分钟)。红灯导致整体交付周期增加约 **30%**(4 次额外周期 / 14 次正常周期,按每次等价工作量估)。

**红灯归因**:4 次中 3 次可被本地门禁拦截(P1 format 漏跑、P2 同左、P4 浮点可被定向测试捕获),1 次不可(pwsh 环境抖动)。

**优化项:**

| 编号 | 措施 | 步骤 | 预期效果 |
|---|---|---|---|
| O1 | **pre-push 本地门禁脚本**:`ruff check . --output-format=github` + `ruff format --check .` + `pytest <本次改动相关测试>` 全绿才允许 push | W1 写入 `.git/hooks/pre-push` 或 justfile 任务;W2 起强制使用 | CI 首推通过率 71.4%(10/14)→ **≥90%**;整体交付周期缩短 **≥20%**(红灯重推周期归零) |
| O2 | **红灯归因时限**:新红灯 30 分钟内对照 E1 清单归因,归因失败升级为独立问题登记 | 即刻生效 | 避免盲目重试 |
| O3 | **知识条目即修即记**:每个关闭的 P 编号同步写入记忆文件 | 即刻生效(本期 P1–P4 均已沉淀) | 经验复用零边际成本 |
